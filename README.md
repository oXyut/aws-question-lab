# AWS Question Lab

AWS の問題を貼り付けると、原文の要件・選択肢の判断・AWS 公式アイコンの構成図を連動させて学べる、日本語の個人向けローカルアプリです。React / TypeScript / Vite / Hono / React Flow / ELK を使用します。

## 起動する

Node.js 22 以上と、ログイン済みの Codex CLI が必要です。アプリ専用の API キーは不要です。CLI の `exec --json --output-schema`、画像入力、読み取り専用サンドボックス、ユーザー設定を読み込まない起動オプションに対応したバージョンを使用してください。

CLI が未導入の場合は [OpenAI 公式の Codex CLI 導入手順](https://learn.chatgpt.com/docs/codex/cli) に従ってインストールし、ターミナルで `codex --version` を実行できることを確認してください。

```sh
npm ci
codex login status
# 未ログインの場合
codex login
npm run dev
```

[http://127.0.0.1:4317](http://127.0.0.1:4317) をブラウザーで開きます。開発時は Hono と Vite の連携サーバーが同じポートで動きます。CLI が使えなくても、固定の「サンプル」で図解の操作を試せます。

サンプルでは追加質問と HTML 出力は無効です。これらは自分の問題から生成・保存した解説で利用できます。

通常の利用向けにビルドして起動する場合：

```sh
npm run build
npm start
```

ローカルアプリというのは画面・サーバー・履歴の保存先が自分の PC にあるという意味です。**AI の読み取り・生成には Codex のオンラインサービスを利用し、入力した問題文や画像を送信します。** 公式資料の検索・照合にもネット接続が必要です。認証と利用枠は手元の Codex の契約・設定に従います。このアプリは AWS リソースを作成しません。

## 使い方

1. 問題文を貼り付けるか、PNG / JPEG / WebP の画像を貼り付け・ドラッグ＆ドロップします。画像は最大 5 枚、各 10 MiB です。既知の正解と元の解説も任意で入力できます。
2. 読み取られた問題文・選択肢・正解を確認し、誤読を修正して解説を生成します。不明瞭な文字は確認事項として表示されます。
3. 原文の強調部分または要件を選ぶと、選択肢の判断理由と関連する図のノード・線が連動します。逆に選択肢を選んで根拠をたどることもできます。
4. 要件のステップ操作で消去の過程を確認します。「要件違反」と「比較上不利」を区別し、公式根拠を確認できない判断は「情報不足／要確認」と表示します。
5. 構成図は選択肢ごとに切り替え、拡大・縮小・ノードの選択・処理順の再生ができます。追加質問をすると新しい版が作られ、過去の版へ戻れます。
6. 履歴から解説を開き、表示中の版を単体 HTML として保存できます。書き出した HTML はファイルを開くだけで、ネット接続なしに要件・選択肢・構成図を操作できます。

単体 HTML には JavaScript / CSS / 使用した AWS アイコン / 選択した版の問題文と解説が含まれます。元のアップロード画像や他の版は含めません。追加の AI 生成、資料の再確認はアプリで行います。出典のリンクを開く場合にはネット接続が必要です。HTML 自体に問題文が含まれるため、共有するとその内容も共有されます。

初版は日本語 UI、AWS 全般、1 回 1 問に対応します。単一選択・複数選択・選択肢のない質問を扱えます。PDF の直接入力、複数人での利用、インターネット公開、試験モードは含みません。

## 設定と保存

設定はプロセスの環境変数で渡します。`.env.example` は設定例であり、単に `.env` を置いても自動では読み込みません。

| 環境変数                 | 既定値・用途                                                          |
| ------------------------ | --------------------------------------------------------------------- |
| `PORT`                   | `4317`。サーバーはループバック限定です。                              |
| `CODEX_BIN`              | `codex`。CLI の実行ファイル名または絶対パス。                         |
| `QUESTION_LAB_MODEL`     | 初回起動時に使うアプリ専用のモデル。既定は `gpt-6-luna`。画面で保存した選択が優先されます。 |
| `CODEX_REASONING_EFFORT` | `low`。学習アプリ用の推論強度。`high` などで明示的に変更できます。 |
| `CODEX_TIMEOUT_MS`       | `600000`。1 回の CLI 実行の制限時間（ミリ秒）。                       |
| `QUESTION_LAB_DATA_DIR`  | アプリディレクトリ内の `.local/`。問題・画像・履歴・ジョブの保存先。  |

```sh
CODEX_TIMEOUT_MS=600000 npm run dev
```

`.env` を使いたい場合は Node.js に明示的に読み込ませます。

```sh
cp .env.example .env
# .env を編集した後
node --env-file=.env --import tsx server/index.ts --dev
```

接続ドロワーの「使用するモデル」から GPT-6 Luna / Sol / Astra を選べます。既定は Luna で、選択は `.local/settings.json` に保存され、Codex CLI のモデル設定とは独立しています。`QUESTION_LAB_MODEL` は保存設定がない初回起動時だけ使われます。推論強度は待ち時間を抑えるためアプリ専用の `low` を既定とし、`CODEX_REASONING_EFFORT` で変更できます。普段の Codex 設定ファイルは変更しません。ユーザーのプラグイン・MCP・フック・ルールは生成に読み込みません。問題文をシェルコマンドへ展開せず、読み取り専用 CLI に標準入力と画像パスとして渡します。

保存先は `documents/`（解説・各版）、`images/`（入力画像）、`jobs/`（再試行用の入力・状態）、`runtime/`（一時作業）、`diagnostics/`（生成した構造化データと検証・修復・CLI時間計測の診断）に分かれます。診断ファイルはジョブIDを名前にし、問題文・生成内容を含むため公開しないでください。履歴削除時には、その履歴に関連する診断も削除します。問題と生成履歴は再起動後も残ります。履歴を削除すると関連するジョブと画像も削除し、他の履歴・ジョブから参照される画像は保持します。`.local/` と `.env` は Git 管理対象外です。保存先を変更する場合も個人データを公開リポジトリに追加しないでください。保存データ全体を破棄したい場合はサーバーを終了し、設定したデータディレクトリを OS のファイル操作で削除できます。ブラウザーに保存した入力の下書きがある場合は、サイトデータも消去してください。

## 根拠とエラーの扱い

新しい解説生成と追加質問では毎回 AWS 公式資料をライブ検索します。サーバーは公式ホスト・取得結果・引用文と本文の一致を検証します。「公式本文と照合済み」は**引用をページ本文で確認できた**という表示であり、AI の推論や推定解答の正しさを保証するものではありません。要件と引用の関係、サービスの制限、リージョンや実行方式は、表示された根拠から確認できます。

根拠を確認できない判断は「要確認」に残します。既知の正解と推定解答が食い違う場合は両方を表示します。画面のサンプルは操作体験のための架空の固定教材で、開くたびに生成・再調査するものではありません。

認証切れ、利用枠の不足、通信エラー、制限時間超過、不正な生成結果はジョブのエラーとして表示します。入力と既存の解説は保持し、中断・再試行できます。生成は同時に 1 件です。画面には経過時間、現在の処理段階、実際の検索・作業通知・出典照合の履歴（最大40件）を表示します。途中で画面を再読み込みしても実行中のジョブへ再接続します。経過時間は完了・失敗・中断時に止まり、通知のない時間も区別します。推定の完了率や、実行していない処理を進捗として表示しません。

サーバーは Host / Origin を検証し、生成・削除 API を他のサイトから操作させない構成です。インターネット公開や LAN 公開のために設計した認証サーバーではありません。HTML 出力は同じ閲覧コンポーネントを同梱し、AI が出した HTML / JavaScript をそのまま実行しません。

生成結果に存在しないノード・接続線の表示用リンクがあった場合は、そのリンクだけを除去します。同じ構成図の要素に同じ要件IDが明示されている場合は、その要素へ強調を補完し、修復内容を解説に表示します。要件の引用、出典、解答、グラフの端点などは変更せず、全参照検証を通った結果だけを保存します。この修復には追加のAI生成を行いません。新しい生成では、各図の要素に付いた要件IDから評価の表示リンクをサーバー側で導出し、同じ参照をAIに重複生成させません。

生成時の出力形式では全選択肢の評価を必須にします。旧出力などで評価が不足した場合は、取得済みの資料・図・要件を渡し、不足した選択肢の評価だけを1回補完します。既存の評価や根拠を置き換えず、補完後も全参照を検証します。関連付けエラー後の再試行では、同一問題の15分以内の復旧可能な生成結果を再利用し、調査の最初からやり直す回数を減らします。再開時も公式資料の本文を再取得して照合します。期限切れ・問題の変更・補修できない不整合がある場合は、新しく調査・生成します。

CLI にはこのアプリ専用の指示を渡し、公式調査を終えてから最終JSONを1回だけ生成させます。コーディング作業用の途中説明が、構造化出力では大きなJSONとして重複生成されることを抑えます。専用指示には未信頼入力の扱いを含め、読み取り専用サンドボックスなどの制限も維持します。設定の仕様は [Codex公式設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference) の `model_instructions_file` / `model_reasoning_effort` を参照してください。診断には処理時間・初回検索の応答までの時間・出力回数/文字数・利用トークン数を保存します。内部の推論内容は記録しません。

## 開発と検証

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

ブラウザーテストは、macOS の標準配置に Google Chrome があればそれを使用し、それ以外は Playwright の Chromium を使用します。後者が未インストールの場合は `npx playwright install chromium` を実行してください。自動テストは、原文引用・グラフ参照・比較条件の意味、CLI イベント・ジョブ再試行、保存、公式出典の検証、エクスポート時の文字エスケープ・アセットの同梱、主要 UI 操作を確認します。CLI の実サービス疎通は認証・通信と利用枠が必要なため、通常の自動テストから分離しています。

共通データ型と参照検証は `shared/schema.ts`、API の内部契約は `CONTRACT.md` にあります。API は読み取り、生成、追加質問、履歴、SSE ジョブ進行、キャンセル・再試行、HTML 出力を提供します。`npm run build` はアプリとオフライン閲覧用 IIFE の両方を構築します。開発中に出力用バンドルがない場合は、最初の HTML 出力時に自動で構築します。

AWS Architecture Icons は公式配布物の SVG を変更せずに同梱しています。出典と各ファイルの SHA-256 は [ATTRIBUTION.md](public/aws-icons/ATTRIBUTION.md) と [manifest.json](public/aws-icons/manifest.json) を参照してください。AWS アイコンの権利は AWS に帰属し、本アプリから別のライセンスを付与するものではありません。使用時は [AWS 公式配布ページの利用案内](https://aws.amazon.com/architecture/icons/) を参照してください。未収録サービスは名称付きの汎用ノードを表示します。本アプリは AWS の公式製品・公式試験問題集ではありません。
