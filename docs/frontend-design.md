# AWS Question Lab の画面設計

## 中心となる体験

AWSを学ぶ個人が、問題文の条件から選択肢の比較理由と構成図をたどる学習用ワークベンチ。原文の引用、AWS公式資料、出典の確認状態、既知の正解と推定の区別を信頼の根拠とする。

既存の濃紺のヘッダー、オレンジの選択状態、公式AWSアイコンを継承する。視覚的な主役は「要件 → 構成 → 判断」の関係。ヒーロー、機能紹介カードの反復、装飾用の図やアニメーションは加えない。

## 画面の役割と優先順位

- 入力：問題文と画像、読み取りボタン、保存・送信範囲の順に読める。任意の正解・元の解説は開閉式。サンプルは補助操作。
- 確認：読み取った原文・選択肢を編集し、確認事項と生成ボタンを隣接させる。未確定箇所を隠さない。
- 図解：原文、要件、AWS構成図、評価の連動を維持する。比較上不利と必須条件違反は別の状態色・文言を使う。
- 処理中：実際に届いた段階と記録、経過時間、中断操作を表示する。架空の完了率・残り時間は表示しない。
- 完了・失敗：結果または次の操作を優先する。詳細記録は開閉可能にして、入力と既存の解説を保つ。

## 実装のルール

- 色・状態色・文字・余白・角丸・影の共通定義は `src/tokens.css`。アプリと単体HTMLで共有する。
- `styles.css` は基礎と共通部品、`studio.css` / `diagram.css` は解説、`shell.css` はアプリの枠組み、`intake.css` は入力・確認と処理状態を担当する。
- 状態は色だけで伝えず、必ずラベルまたはアイコンと組み合わせる。
- キーボード操作、見えるフォーカス、44pxを目安とした主操作のタッチ領域、reduced-motionを守る。
- 幅375 / 768 / 1440pxで、横方向のページはみ出し、主操作の欠落、長い日本語の折り返しを確認する。
- 問題や生成履歴は検証文書・スクリーンショットとしてGitに含めない。サンプルと合成データを使う。

## 変更時の確認

入力の空・入力済み・画像添付・任意項目、読み取り確認、生成中、中断、失敗・再試行、履歴、図解の選択・ステップ、モバイルのタブ、単体HTMLを対象にする。既存の `design-qa.md` とE2Eを再利用し、変更した挙動だけ回帰テストを追加する。

`npm run typecheck`、`npm test`、`npm run build` を実行。ブラウザの表示・キーボード操作は利用中のブラウザツールで確認し、E2Eは既存CIで実行する。
