# AWS Question Lab の画面設計

## 中心となる体験

AWSを学ぶ個人が、問題文の条件から選択肢の比較理由と構成図をたどる学習用ワークベンチ。原文の引用、AWS公式資料、出典の確認状態、既知の正解と推定の区別を信頼の根拠とする。

濃紺の56pxヘッダーに新しい問題・HTML保存・履歴・接続を集約する。常設サイドバーや同じ設定を開く重複入口は置かない。オレンジの選択状態と公式AWSアイコンを継承する。視覚的な主役は「原文 → 解答の要点 → 要件の比較 → 構成図」の関係。処理中の動きには意味を持たせ、架空の進捗は表示しない。

## 画面の役割と優先順位

- 入力：問題文と画像、読み取りボタン、保存・送信範囲の順に読める。任意の正解・元の解説は開閉式。サンプルは補助操作。
- 確認：読み取った原文・選択肢を編集し、確認事項と生成ボタンを隣接させる。未確定箇所を隠さない。
- 図解：原文は高さ制限や内部スクロールを設けず全文表示。解答・要点・判断の前提・重要な注意を直後に表示し、未照合・正解の不一致を隠さない。要件の比較と選択肢を横断した評価の下に全幅の構成図を置く。選択と図の連動を維持し、比較上不利と必須条件違反を別の状態色・文言で示す。スマートフォンでも同じ読む順序を保つ。用語と出典の全文は末尾の開閉式に集約する。
- 処理中：右下の展開可能な固定サイズパネルに実際の段階・記録・経過時間・中断を表示する。記録が増えてもパネルは伸ばさず内部スクロール。段階は矢印で結び、実行中のノードと接続線だけを動かす。処理開始時にフォーカスやページ位置を奪わない。架空の完了率・残り時間は表示しない。
- 完了・失敗：完了時はパネルを自動で最小化し、失敗時は理由と再試行を展開して表示。入力と既存の解説を保つ。詳細記録はいつでも開閉できる。

## 実装のルール

- 色・状態色・文字・余白・角丸・影の共通定義は `src/tokens.css`。アプリと単体HTMLで共有する。
- `styles.css` は基礎と共通部品、`studio.css` / `diagram.css` は解説、`shell.css` はアプリの枠組み、`intake.css` は入力・確認、`progress.css` は処理パネルを担当する。
- 状態は色だけで伝えず、必ずラベルまたはアイコンと組み合わせる。
- キーボード操作、見えるフォーカス、44pxを目安とした主操作のタッチ領域、reduced-motionを守る。
- 幅375 / 768 / 1440pxで、横方向のページはみ出し、主操作の欠落、長い日本語の折り返しを確認する。
- 問題や生成履歴は検証文書・スクリーンショットとしてGitに含めない。サンプルと合成データを使う。

## 変更時の確認

入力の空・入力済み・画像添付・任意項目、読み取り確認、生成中、中断、失敗・再試行、履歴、図解の選択・ステップ、モバイルの縦方向の読み順、単体HTMLを対象にする。既存の `design-qa.md` とE2Eを再利用し、変更した挙動だけ回帰テストを追加する。

`npm run typecheck`、`npm test`、`npm run build` を実行。ブラウザの表示・キーボード操作は利用中のブラウザツールで確認し、E2Eは既存CIで実行する。
